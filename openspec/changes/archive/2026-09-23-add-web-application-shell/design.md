# Design — add-web-application-shell

## Context

Change 01 delivered a single SSR page. This change adds the router, layouts, and boundaries
that every later route-bearing capability extends. Authentication does not exist yet, so the
session boundary is defined as an injected contract with an anonymous default resolver; the
account-authentication change supplies the cookie-backed implementation without changing
route or layout code.

## Requirements Driving the Design

- `Route-addressable application shell`
- `SSR and hydration continuity`
- `Application boundary handling`

## Architecture

- **Routes** (`crates/web/src/routes.rs`) use `leptos_router` 0.8:
  - Public: `/` landing, `/login` sign-in placeholder, `/*any` not-found.
  - Protected: `/inbox`, `/today`, `/upcoming`, `/anytime`, `/someday`, `/logbook`,
    `/tomorrow` (placeholder for the special-lists change), `/projects`, `/areas`,
    `/areas/:area_id`, `/projects/:project_id`, `/todos/:todo_id`, `/settings`.
- **Layouts** (`crates/web/src/layouts.rs`):
  - `PublicLayout` — centered surface for landing/sign-in/boundary pages.
  - `AppLayout` — primary navigation (`<nav aria-label="Primary">`) plus `<main>` content.
- **Session boundary** (`crates/web/src/session.rs`):
  - `momentum_app::session::SessionState` (`Anonymous` | `Authenticated(AccountSession)`).
  - `SessionResolver` trait (web crate) resolves state from request headers; the server
    provides the active resolver via `leptos_routes_with_context`, so tests and the future
    auth change inject real implementations.
  - `SessionProvider` provides an `RwSignal<SessionState>`; SSR computes it from
    `http::request::Parts` context + resolver, hydrate reads a JSON bootstrap element rendered
    by the server, falling back to `Anonymous`.
  - `Protected` renders `AppLayout` for authenticated sessions and the unauthorized boundary
    otherwise. Protected route content never renders for anonymous sessions.
- **Boundaries** (`crates/web/src/boundaries.rs`):
  - `Loading` — `role="status"` + `aria-live="polite"` indicator.
  - `NotFound`, `Unauthorized` — public-layout pages with navigation recovery links.
  - `ErrorView` + `AppBoundary` — `ErrorBoundary` with a recovery action.
- **Server** (`crates/web/src/server.rs`): `generate_route_list(App)` plus
  `leptos_routes_with_context` so SSR handles every declared route; `/healthz` and `/readyz`
  remain plain Axum routes; `file_and_error_handler` keeps static asset serving and
  non-route fallback working.

## Data and Persistence

No persistence. `AccountId` is added to `momentum-domain::ids` as a UUID newtype so the
session contract has a canonical identity type; the accounts schema arrives in change 06.

## Offline and Sync

Not applicable yet. Route/session state is canonical and must not be duplicated in client
state; the client re-renders from the same context on hydration.

## UI and Accessibility

- Landmarks: `nav`, `main`, `header`; skip-link deferred to the accessibility change.
- Boundary pages are plain semantic pages with a single primary action.
- Loading indicator is a live region; error fallback has `role="alert"`.
- Responsive breakpoints are deliberate in change 04; this change uses a simple two-column
  shell that does not overflow at narrow widths.

## Error Handling

- Unknown routes render the not-found boundary, not a raw 404 page.
- Protected routes render the unauthorized boundary, never partial task UI.
- `ErrorBoundary` catches rendering errors in route content and offers "Reload" and
  "Go to Inbox" recovery actions.

## Testing Strategy

- Integration tests through the Axum router (`tower::ServiceExt::oneshot`):
  - every built-in list route renders its heading when an authenticated resolver is injected;
  - `/today` renders the unauthorized boundary for the anonymous resolver;
  - unknown paths render the not-found boundary;
  - SSR HTML contains the session bootstrap JSON element.
- Unit SSR tests for `Loading`, `NotFound`, `Unauthorized`, and `ErrorView` components.
- Hydration continuity is exercised by asserting the server HTML contains the destination
  markup and bootstrap element that the WASM client consumes; full browser E2E arrives with
  the visual/behavior parity suites.

## Rollout / Migration

Greenfield shell; no data formats change. Safe for existing development databases.

## Open Questions Resolved From the Repository

- **Session injection**: `leptos_axum` provides `http::request::Parts` as reactive context, so
  the resolver reads headers inside the reactive owner rather than in middleware.
- **Hydration bootstrap**: session JSON is embedded as a `type="application/json"` element
  generated by Rust (no inline script, no handwritten JS).
- **Router testing**: `leptos_router` 0.8 has no public location mock; tests exercise routes
  through the Axum integration instead.
