# Design — add-automation-api

## Context

Authentication already provides an opaque token generator whose `hash` is deterministic (used for
lookup tokens), and the command layer single-sources all mutations. The API reuses both.

## Requirements Driving the Design

- `Scoped API tokens`
- `Command-layer API`
- `Stable API contract`

## Architecture

- Tokens are generated by the existing `TokenGenerator`; only `hash(token)` is persisted, so
  authentication hashes the presented bearer and looks it up directly. `create`/`rotate` return
  the plaintext exactly once; `revoke` sets a timestamp and `rotate` refuses revoked tokens.
  Scopes are stored per token; `ApiPrincipal::has` makes write imply read.
- `/api/v1/todos` maps requests to `TodoService` calls only; DTOs are explicit (`ApiTodo`), the
  scope query uses a fixed allow-list, bodies parse strictly, and create applies metadata with
  the same compensation pattern as Quick Entry.
- Errors are typed JSON with stable codes (`unauthorized`, `forbidden`, `invalid_request`,
  `not_found`, `unavailable`, `internal`).

## Data and Persistence

- Migration 0007 `api_tokens` with a unique hash, per-account index, and revocation timestamps.
  Plaintext tokens are never persisted.

## Offline and Sync

- API mutations flow through the same commands/change log as UI mutations; automation and the
  outbox converge on identical semantics.

## UI and Accessibility

- Settings lists tokens with scopes and revoked state and offers revoke/rotate; the view-once
  plaintext is displayed once after creation/rotation via a redirect parameter (never stored).

## Error Handling

- Missing/invalid tokens → 401; insufficient scope → 403; malformed values → 400; unknown ids →
  404; unconfigured service → 503; unexpected failures → 500.

## Testing Strategy

- App unit test for scope semantics; testkit tests for view-once creation, authentication with
  last-used tracking, rotation invalidating the old token, revocation blocking use, and refused
  rotation of revoked tokens; web tests for bearer enforcement, read-vs-write scopes, CRUD/action
  flows with typed errors, rotation/revocation effects, and the settings view-once flow.

## Rollout / Migration

- Migration 0007 is additive and reversible.

## Open Questions the Agent Must Resolve From the Repository

- Resolved: deterministic token hashing (existing generator) is used instead of a salted password
  hash because lookup must be by hash; entropy comes from the generator, and the plaintext is
  shown once.
